# rqlite capabilities

Roadmap 2.1 gate, Work Item WI-2026-11-21-002. Tested against rqlite v10.7.4 (commit `4452a98`, image `rqlite/rqlite:10.7.4`). Every row has an automated test in `ci/rqlite/`, run by `ci/rqlite/run-all.sh` and by the OneDev job `rqlite-capabilities`. Each test starts its own nodes on loopback.

| # | Capability | Exists | How | Limits | Tests |
| --- | --- | --- | --- | --- | --- |
| 1 | A node changes between voter and non-voter at runtime | Yes | `POST /demote` and `POST /promote` with body `{"id":"<node>"}`; membership with `GET /nodes?ver=2&nonvoters` (field `voter`) | One node per call. Keeping the voter total odd is Akela's job (Membership Manager). | `voter-to-nonvoter`, `nonvoter-to-voter` |
| 2 | Leadership is transferred to a chosen node | Yes | `POST /leader?wait` with body `{"id":"<node>"}` | Writes are rejected while a transfer is in progress (hashicorp/raft `ErrLeadershipTransferInProgress`). | `leader-transfer` |
| 3 | Unreachable nodes are removed, except the Cloud Node | Partly | rqlite's own reaper (`-raft-reap-node-timeout`, `-raft-reap-read-only-node-timeout`) has one timeout for all voters and one for all non-voters and cannot exclude a node, so it must stay off. Akela removes nodes itself: the Membership Manager reads `reachable` per node from the Leader's `GET /nodes?ver=2&nonvoters` and calls `DELETE /remove` with `{"id":"<node>"}`, skipping the Cloud Node. | Removal needs a Leader. The removal timeout is kept by the Membership Manager, not by rqlite. | `remove-unreachable`, `builtin-reaper-spares-no-node` |
| 4 | Backup and restore | Yes | `GET /db/backup` on a running node returns a SQLite file; `POST /boot` (`Content-Type: application/octet-stream`) loads it into a new single-node cluster | Tested only into a new single-node cluster, as the manual procedures need. | `backup-restore` |
| 5 | CDC is emitted, including with a new `service_id` | Yes | `-cdc-config <file>` with `{"endpoint": "...", "service_id": "..."}`. The Leader posts envelopes `{service_id, node_id, payload: [{index, commit_timestamp, events: [{op, table, new_row_id, before, after}]}]}`. A cluster recreated from a backup with a new `service_id` emits under the new one. | `service_id` is read at startup. A recreated cluster restarts Raft indexes (G2 row at index 4 after G1 reached 23), so the generation must be part of the dedupe key. The endpoint must answer 2xx. | `cdc-events`, `cdc-new-service-id` |
| 6 | A follower forwards writes to the Leader | Yes | Writes sent to any node are forwarded; header `X-Rqlite-Served-By` carries the Leader's Raft address | None found. | `follower-forwards-writes` |
| 7 | Each read call chooses its consistency level | Yes | Query parameter `level` (`none`, `weak`, `linearizable`, `strong`, `auto`) per call; `none` reads the local copy even with no Leader; `strong` goes through the Leader | A missing or unknown `level` silently means `weak` (`command.LevelFromString`), so Akela's client must always send one. Errors can come back as HTTP 200 with an `error` field and no rows; clients must check `error`, not only the status code. | `read-level-none-local`, `read-level-strong-needs-leader` |
| 8 | Approved-list changes apply by restarting `rqlited` one node at a time, Leader last | Yes | The approved self-signed certificates, concatenated, are the CA file for `-node-ca-cert` and `-http-ca-cert` with `-node-verify-client` and `-http-verify-client`. An unapproved certificate gets TLS alert `unknown ca` on both ports. A round restarts each node with the new file after the previous one caught up, then transfers leadership and restarts the old Leader. A machine that was off reads the list from the Location Cluster with its own certificate before starting. | The CA file is read only at startup, so every approval or block restarts every node. With a single voter, writes paused about 2 s in the local run. | `trust-unapproved-refused`, `trust-approve-rolling-restart`, `trust-block-rolling-restart`, `trust-single-voter-restart`, `trust-machine-off-during-change` |

## Gate result

Every capability exists except the native form of row 3. RFC-0001 C-DEPARTURE asks that unreachable nodes be removed and that the Cloud Node be spared, without requiring rqlite's own reaper, so the Membership Manager meets it through `/nodes` and `/remove` and no clause or ADR needs to reopen.
